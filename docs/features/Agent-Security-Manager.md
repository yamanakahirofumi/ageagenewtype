# エージェント・セキュリティマネージャ仕様書

本ドキュメントでは、AIエージェントが自律動作する際、AIの回答や生成されたコマンドによってシステムが暴走したり、予期せぬ破壊的・不正な操作を行ったりすることを防止するためのセキュリティマネージャ機能の仕様を定義します。

## 1. 概要

### 背景と目的
生成AIや自律型エージェントは、ファイル操作、外部プログラム実行、Webアクセスなどの「ツール」を利用して高度なタスクを自動化できます。しかし、AIの出力やプロンプトインジェクション、予期せぬ解釈によって、機密ファイルを削除・流出させたり、不正なプログラムを実行させられたりする危険性（暴走リスク）があります。
本機能は、エージェントの操作範囲を強力に制限し、安心・安全なデスクトップ実行環境を提供することを目的とします。

### 基本設計方針
- **Default Deny（原則禁止）**: あらかじめ明示的に許可された操作以外は、すべて拒否します。
- **許可リスト（Allowlist）方式**: 非常に単純かつ確実に動作するよう、許可する対象のみを定義します。複雑な設定による設定ミスを防ぐため、簡潔で分かりやすいフォーマットとします。
- **ワイルドカードと否定のサポート**: 柔軟な設定を容易にするため、アスタリスク（`*`）による前方・後方・部分一致と、エクスクラメーションマーク（`!`）による特定の除外（否定）をサポートします。
- **プレースホルダー（マジックワード）のサポート**: ファイルアクセスにおいて、実行環境ごとに異なる作業ディレクトリを柔軟かつポータブルに指定できるよう、特別なマジックワード（`${WORKSPACE_DIR}` など）をサポートします。

## 2. セキュリティ管理対象（3つのカテゴリ）

セキュリティマネージャは、エージェントが実行可能な以下の3つのアクションカテゴリを監視・制限します。

1. **ファイルアクセス（File Access）**
   - エージェントが読み書き、作成、削除できるファイルやディレクトリのパスを制限します。
2. **外部プログラム実行（Program Execution）**
   - エージェントがOSのサブプロセスとして起動・実行できるコマンドや実行可能ファイルのパスを制限します。
3. **HTTP/HTTPS接続（HTTP URL Access）**
   - エージェントが外部からデータを取得したり、外部へデータを送信したりする際の宛先URLを制限します。

## 3. 設定ファイル（ルール定義）の形式

設定ファイルは簡潔なプレーンテキスト、またはJSON形式で定義します。ここでは、エンドユーザーやシステム管理者が最も直感的に編集できるシンプルなルールベーステキスト形式（`.conf`）を標準とします。

### 記述形式
```ini
[file-access]
${WORKSPACE_DIR}/docs/*
!${WORKSPACE_DIR}/docs/secrets/*

[program-execution]
# 初期状態（デフォルト）で許可される参照系コマンド
ls
find
cat
grep
pwd
# 特定ディレクトリ配下を一括許可するが、特定のコマンドのみ拒否する設定例
!rm
!poweroff
/usr/bin/*
# 開発用許可
git
mvn

[http-url]
https://api.github.com/*
https://*.openai.com/*
```

### 設定ファイルの基本仕様
- 空行および `#` または `;` で始まる行はコメントとして無視されます。
- セクション `[file-access]`, `[program-execution]`, `[http-url]` で各カテゴリのルール群を開始します。
- 各行が1つのパターン（ルール）を表します。
- 先頭に `!` が付いているルールは**否定ルール（除外設定）**です。
- パターン内の `*` は**ワイルドカード（任意の0文字以上の文字列）**として扱われます。

## 4. 評価アルゴリズムとルール適合判定

セキュリティマネージャがエージェントからのアクセス要求を判定する際、以下のアルゴリズムに則って評価します。

### 評価の順序とルール
1. 要求されたアクション（例：`/workspace/docs/secrets/passwords.txt` への書き込み）に対し、該当するカテゴリのルール一覧を取得します。
2. ルールは**上から順（記述順）**に評価されます。
3. **否定ルール（`!` で始まるパターン）**にマッチした場合：
   - その時点で判定を打ち切り、**「拒否（不許可）」**と決定します。
4. **許可ルール（通常のパターン）**にマッチした場合：
   - その時点で判定を打ち切り、**「許可」**と決定します。
5. リスト内のすべてのルールにマッチしなかった場合：
   - デフォルトルールが適用され、**「拒否（不許可）」**と決定します（Default Deny）。

### 具体的な判定例
以下の設定を例とします（作業ディレクトリ `${WORKSPACE_DIR}` が `/workspace` であるとします）：
```ini
[file-access]
!${WORKSPACE_DIR}/docs/secrets/*
${WORKSPACE_DIR}/docs/*
```

- **ケースA**: `/workspace/docs/manual.md` へのアクセス要求
  1. `!${WORKSPACE_DIR}/docs/secrets/*` にマッチするか？ -> しない。
  2. `${WORKSPACE_DIR}/docs/*` にマッチするか？ -> マッチする。
  3. **判定結果**: **許可**

- **ケースB**: `/workspace/docs/secrets/api-key.txt` へのアクセス要求
  1. `!${WORKSPACE_DIR}/docs/secrets/*` にマッチするか？ -> マッチする（否定ルール）。
  2. その時点で評価終了。
  3. **判定結果**: **拒否**

- **ケースC**: `/etc/passwd` へのアクセス要求
  1. すべてのルールにマッチしない。
  2. **判定結果**: **拒否**（Default Denyによる）

## 5. カテゴリ別のマッチング仕様

| カテゴリ | 判定対象 | マッチング仕様 | 設定例 |
| :--- | :--- | :--- | :--- |
| **ファイルアクセス** | 操作対象のファイル/フォルダの絶対パス | ディレクトリ境界、ファイル名部分に `*` を使用可能。<br>**プレースホルダー（マジックワード）**: `${WORKSPACE_DIR}` は実行時にアプリケーションが現在開いているワークスペース（作業ディレクトリ）の絶対パスに動的に置換されます。 | `!*.key` (拡張子.keyを拒否)<br>`${WORKSPACE_DIR}/src/*` (作業ディレクトリのsrc配下の直下ファイルのみ許可)<br>`${WORKSPACE_DIR}/**` (作業ディレクトリ配下の全サブフォルダ含むファイルを許可) |
| **外部プログラム実行** | 起動しようとするコマンド名、または実行ファイルの絶対パス | コマンド名そのもの、またはパス名の一部に `*` を使用可能。<br>**初期許可コマンド**: 環境を変更しない（読み取り・参照専用の）Linux/Unix標準コマンド（例: `ls`, `find`, `cat`, `grep`, `pwd`）は、初期状態で許可リストに事前定義されます。 | `git` (gitコマンドのみ許可)<br>`mvn` (mvnコマンドのみ許可)<br>`/usr/bin/*` (/usr/bin配下のすべてのプログラムを許可)<br>`!rm` (rmコマンドを明示的に拒否) |
| **HTTP URL接続** | リクエスト先の完全なURL (プロトコル、ホスト、ポート、パス) | スキームやホスト、パスに `*` を使用可能。 | `https://api.github.com/*` (GitHub APIのみ許可)<br>`https://*.openai.com/*` (OpenAIのサブドメイン含めすべて許可)<br>`!*malicious*` (URL内にmaliciousを含むものを拒否) |

## 6. GUIにおけるセキュリティ管理と一時的な無効化

ユーザーの利便性と開発・デバッグ時の柔軟性を考慮し、GUI上でセキュリティマネージャの有効・無効を制御する機能をサポートします。

### GUI上のコントロールと表示
- **セキュリティ有効/無効トグル（スイッチ・チェックボックス）**
  - チャット部またはアプリケーション設定パネルに、「エージェント制限を有効にする（推奨）」トグルを配置します。
  - デフォルトでは**「有効（ON）」**となっており、安全な状態を維持します。
- **一時的な無効化（Bypass）機能**
  - ユーザーが独自の開発作業や意図したシステム操作を行う際、セキュリティマネージャを一時的に「無効（OFF）」に切り替えることができます。
- **無効化時の警告表示（UX配慮）**
  - トグルを「無効」に切り替えた際、**「セキュリティ制限を無効化すると、AIエージェントによるファイルの破壊、不要なコマンド実行、外部へのデータ送信のリスクが高まります。無効化しますか？」**という確認ダイアログ（Warning Alert）をポップアップ表示します。
  - 無効化されている間、チャット画面の上部に常時赤い警告バナー（例：「⚠️ セキュリティ制限が無効化されています」）を表示し、ユーザーに注意を促します。
- **自動復帰（再有効化）オプション**
  - 安全のため、「無効化後 10分経過時」または「現在のチャットセッション終了時」に、自動的にセキュリティマネージャをONに戻す自動復帰機能をサポートします。

## 7. 異常検知時の挙動

エージェントが許可リストに含まれない（または否定リストに合致する）危険な操作を試みた場合、セキュリティマネージャは以下のプロセスを実行します。

1. **処理の即時遮断（ブロック）**
   - 対象のアクション（ファイルの読み書き、プロセスの起動、HTTPリクエストの送信）を物理的に実行させず、即座に中断します。
   - エージェント実行コンテキストに対して、実行時例外 `AgentSecurityException` をスローします。
2. **ユーザーへの警告表示（UI/UX連携）**
   - アプリケーション画面（AIチャット部、または通知ダイアログ）に、「セキュリティポリシーによってブロックされた操作」として、分かりやすく警告を表示します。
   - 表示項目：ブロックされたカテゴリ、試行された具体的な操作（パス、コマンド、URLなど）。
3. **セキュリティ監査ログの記録**
   - 拒否された操作の履歴を専用の監査ログ（またはアプリケーションログ）に記録します。
   - 出力内容：日時、エラー内容、試行された操作内容、適合した否定ルール（あれば）。
   - これにより、ユーザーおよび開発者は、AIエージェントがどのような文脈で制限を超えようとしたかを後から調査・分析できます。
