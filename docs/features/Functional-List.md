# 機能一覧 (Functional List)

本ドキュメントでは、Ollama および LangChain4j を活用した IDE 風生成AIデスクトップアプリケーションで提供するカテゴリ別の詳細な機能一覧を定義します。

## 1. 概要

本アプリケーションは、ローカル環境で動作する Ollama LLM と統合され、ファイル編集、AI チャット、自律型ワークフロー実行、セキュリティ制御、および Git 操作を統合した開発・執筆環境を提供します。

---

## 2. カテゴリ別機能一覧

### 2.1. LLM 連携・通信機能
| 機能ID | 機能名 | 詳細説明 |
| :--- | :--- | :--- |
| LLM-01 | ローカル LLM 接続 | LangChain4j (`langchain4j-ollama`) を利用して、ローカル Ollama サービス (`http://localhost:11434`) へ接続しテキスト生成・対話を実行。 |
| LLM-02 | 利用可能モデル動的取得 | Ollama サーバにロードされているモデル一覧 (`llama3.2`, `mistral` 等) を自動取得し、UIドロップダウンに反映。 |
| LLM-03 | ストリーミング応答 | `StreamingChatLanguageModel` / `TokenStream` により生成AIのレスポンスをリアルタイムで逐次追記表示。 |
| LLM-04 | 通信タイムアウト制御 | 接続確認 (5秒)、モデル一覧取得 (10秒)、チャット/ストリーミング生成 (180秒) の段階的タイムアウト管理。 |

### 2.2. IDE 風 GUI 画面機能
| 機能ID | 機能名 | 詳細説明 |
| :--- | :--- | :--- |
| GUI-01 | 3分割 SplitPane レイアウト | ファイルツリー部、エディタ部、チャット部を統合配置し、ドラッグ操作で領域幅を調整可能。 |
| GUI-02 | ワークスペースファイルツリー | 選択したワークスペースのフォルダ・ファイル階層を表示し、新規作成・削除・名前変更等のコンテキストメニューを提供。 |
| GUI-03 | タブ式テキストエディタ | 複数ファイルを同時に開いてタブ切り替え、テキスト編集、保存 (`Ctrl+S`) が可能。 |
| GUI-04 | インライン可変長チャット表示 | 透過・ボーダーレス化された TextArea と隠し Text ヘルパーノードの高さバインディングによる選択・コピー可能なチャットメッセージ描画。 |
| GUI-05 | 接続ステータス表示 | ステータスバー上で Ollama 接続状態 (Connected / Disconnected) およびアクティブモデル名を常時表示。 |

### 2.3. AI ワークフロー実行エンジン機能
| 機能ID | 機能名 | 詳細説明 |
| :--- | :--- | :--- |
| WF-01 | 定義済みワークフロー実行 | 組み込み JSON ワークフロー (`source-code-creation` 等) またはユーザー定義 (`${WORKSPACE}/.age/workflows/`) の多段階タスク実行。 |
| WF-02 | 出力・検証サイクル | 「生成 (Output) 段階の後に必ず検証 (Verify) 段階を実行」する品質保証原則を強制。 |
| WF-03 | 自動テスト・AI自己検証 | 検証ステップにおいて Maven コンパイル・テストや AI による出力コードの整合性チェックを自動実行。 |
| WF-04 | フィードバックループバック | 検証失敗時に指摘事項をフィードバックとして前の生成ステップに付与し、自動再実行を行うリトライ機構。 |
| WF-05 | 対話型 Clarification ループ | ステップ応答に `CLARIFICATION_REQUIRED` が含まれる場合、一時停止してユーザーへ追加入力を求め、応答をフィードバックとして再実行。 |
| WF-06 | ワークフロー選択 GUI | 既存モデル選択下に ComboBox を配置し、Standard Chat / Auto Detect / 各種定義済みワークフローの手動切替をサポート。 |

### 2.4. サポート AI Capability 拡張機能
| 機能ID | 機能名 | 詳細説明 |
| :--- | :--- | :--- |
| SUP-01 | Capability 拡張基盤 | `SupportAICapability` インターフェースによる動的機能プラグイン・レジストリ構成 (`SupportAiService`)。 |
| SUP-02 | セキュリティチェック Capability | `security-check` 能力によるファイルアクセスや実行許可の自律的検証の移譲。 |
| SUP-03 | ワークフロー一覧取得 Capability | `list-workflows` 能力により、利用可能なワークフロー一覧の即時取得・フォーマット出力。 |
| SUP-04 | ファイル存在調査 Capability | `file-lookup` 能力により、指定されたパスのファイル・ディレクトリ存在確認を実行。 |
| SUP-05 | ワークフロー判定・自然言語インターセプト | プロンプト解析により手動選択のオーバーライドやファイルアクセス要否 (`fileAccessNeeded`) を評価。キーワード照会 (`どんなワークフロー`) 時の即時回答。 |

### 2.5. セキュリティマネージャ機能
| 機能ID | 機能名 | 詳細説明 |
| :--- | :--- | :--- |
| SEC-01 | ルールベースセキュリティ | `security_rules.conf` に基づき `file-access`, `program-execution`, `http-url` の 3 カテゴリでアクセス制御。 |
| SEC-02 | ワイルドカード・相対パス対応 | ワークスペース相対パスやワイルドカード (`*`)、否定ルールによるフレキシブルな判定。 |
| SEC-03 | 無効化プレフィックス制御 | ルール個別で `#inactive#` プレフィックスを付与し、一時無効化と再有効化を保持。 |
| SEC-04 | セキュリティマネージャ GUI | TableView によるルール一覧表示、インライン CheckBox での有効/無効切替、および保存機能 (`btnSaveRules`)。 |
| SEC-05 | 監査ログ (Audit Log) | セキュリティ判定履歴 (ALLOW / DENY / Bypassed) のタイムスタンプ付き記録・保持。 |

### 2.6. ワークスペースファイル参照機能
| 機能ID | 機能名 | 詳細説明 |
| :--- | :--- | :--- |
| WFA-01 | ワークスペースファイル取得 | サポート AI がファイル参照の必要性を検知した場合、該当ファイルの内容を事前読み込み。 |
| WFA-02 | セキュリティ安全連携 | `SecurityService` の認可を受けたファイルのみをコンテキストに統合し、安全なアクセスを保障。 |
| WFA-03 | モデル依存非分離設計 | Tool Calling 非対応 LLM モデルであっても安全にファイル内容をプロンプトコンテキストとして利用可能。 |

### 2.7. マルチモデル・オーケストレーション機能
| 機能ID | 機能名 | 詳細説明 |
| :--- | :--- | :--- |
| MMO-01 | 役割分担パイプライン | 「要件定義」「コード実装」「レビュー」などのフェーズ毎に最適な小規模モデル（7B〜8Bクラス）を順次割り当てて実行。 |
| MMO-02 | アンサンブル合意形成・部分合成 | 複数モデルの並列実行結果に対し構造化採点・集計を行い、多数決選択 (`MAJORITY_VOTE`) または最良部分合成 (`BEST_PARTS_SYNTHESIS`) により最適な解を抽出・統合。 |
| MMO-03 | 相互レビュー・自己反省ルーティング | 相互レビュー (Peer Review) および生成モデル自身による自己反省 (Self-Reflection) により指摘事項をレポート化し、推論特化モデルへ自動修正ルーティング。 |
| MMO-04 | マルチモデルUI可視化 | チャット画面・ステータスバーにて「現在応答中のモデル名」およびアンサンブル比較プロセスをアコーディオン表示。 |

### 2.8. Git 操作 GUI 機能
| 機能ID | 機能名 | 詳細説明 |
| :--- | :--- | :--- |
| GIT-01 | リポジトリ状態表示 | JGit を用いたワークスペースのリポジトリ状態 (ブランチ、Ahead/Behind コミット数、変更ファイル) の可視化。 |
| GIT-02 | 基本 Git 操作 GUI | インターフェース上からの `init`, `fetch`, `pull`, `commit`, `push`, `checkout`, `branch作成` の実行。 |
| GIT-03 | ステージング選択 | 変更ファイル一覧での CheckBox 操作によるステージ (`git add`) / アンステージ (`git reset`) の切替。 |
| GIT-04 | 非同期バックグラウンド実行 | 重い Git 操作を別スレッド (`Task` / `ExecutorService`) で処理し、JavaFX メイン UI をフリーズさせないノンブロッキング設計。 |
| GIT-05 | 競合検知・競合解決支援 | マージ・pull 競合発生時の競合マーカー強調表示とマージコミット誘導フロー。 |
