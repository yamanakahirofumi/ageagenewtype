# エージェント・セキュリティマネージャ GUI仕様書

本ドキュメントでは、AIエージェントの安全な自律動作を制御する「エージェント・セキュリティマネージャ」におけるユーザーインターフェース（GUI）の画面構成、表示コンポーネント、インタラクション、およびUI/UXの振る舞いについて詳細に定義します。
セキュリティ制限の有効・無効化、ポリシー編集、異常検知時の警告、および履歴監査を安全かつ直感的に管理できるGUIの提供を目的とします。

## 1. 概要

### 開発の目的と背景
AIエージェントがファイル操作やコマンド実行、Webアクセスを行う際、[エージェント・セキュリティマネージャ仕様書](Agent-Security-Manager.md) に基づき安全に制限・監査を行う必要があります。
しかし、制限の状況やブロックされた操作、適用ルールなどをユーザーが視覚的に把握できないと、開発・執筆の作業効率が著しく低下したり、意図しないまま制限をオフにしてシステムを危険に晒したりするリスクが生じます。
本GUI設計は、セキュリティ状態の可視化と安全なバイパス制御を両立させるためのインターフェースを提供します。

### 基本方針
- **安全第一の可視性**: セキュリティ制限が「無効」になっている危険な状態は、一目で分かるように強力な視覚的警告（赤のバナーや警告マークなど）を常時表示します。
- **誤操作防止（Failsafe）**: 制限の無効化には確認用ポップアップ（警告ダイアログ）を挟み、安易なバイパスを防止します。また、自動復帰（タイマー）による安全網を提供します。
- **直感的な監査（Auditability）**: ブロックされた危険な操作（カテゴリ、具体的な対象）をポップアップやログビューで明確に通知し、ユーザーが「何が、なぜ拒否されたか」を即座に特定できるようにします。

## 2. 画面レイアウトと表示コンポーネント

セキュリティマネージャのGUIは、主に「チャット部のヘッダー/ステータス領域」「セキュリティ設定ダイアログ・設定パネル」「異常検知アラート」の3つで構成されます。

### 画面構成図（モックアップ）
```
+-----------------------------------------------------------------------------------+
|  [Menu Bar]  File  Edit  View  Tools  Help                                        |
+-------------------+----------------------------------+----------------------------+
| ファイルツリー部  | エディタ部                       | チャット部                 |
| (File Tree Pane)  | (Editor Pane)                    | (Chat Pane)                |
|                   |                                  |                            |
|                   |                                  | [⚠️ セキュリティ無効バナー ]|
|                   |                                  | -------------------------- |
|                   |                                  | AI CHAT   [Security Status]|
|                   |                                  | -------------------------- |
|                   |                                  | ...                        |
+-------------------+----------------------------------+----------------------------+
```

### 主要コンポーネント一覧

| 画面/コンポーネント | 配置場所 | コントロール/表示項目 | 役割 |
| :--- | :--- | :--- | :--- |
| **セキュリティ状況バッジ** | チャット部ヘッダー | `Label` (シールド型アイコン 🛡️ / ⚠️) | 現在のセキュリティ制限のステータス（有効/無効）をコンパクトに表示。クリックで設定を開く。 |
| **一時無効化警告バナー** | チャット部最上部 | `HBox` (背景色: 赤/黄、テキスト: 白) | セキュリティマネージャが無効化されている間に常時表示される警告。再有効化ボタンを配置。 |
| **設定用トグルスイッチ** | 設定パネル内 | `ToggleButton` / `CheckBox` | エージェントの制限（ファイル/コマンド/HTTP）の一括有効・無効を切り替える。 |
| **ルール定義エディタ** | 設定パネル内 | `TextArea` (等幅フォント) | `.conf` 形式の許可/拒否ルールを直接編集・保存するエリア。 |
| **自動復帰オプション** | 設定パネル内 | `ComboBox` / `Spinner` | 無効化後、自動的に再有効化する時間（5分、10分、30分、セッション終了時、自動復帰なし）の選択。 |
| **異常検知ブロックポップアップ** | 割り込みダイアログ | `Alert` (Type: WARNING / ERROR) | 危険な操作がブロックされた際、瞬時にフォアグラウンドに表示される詳細アラート。 |

## 3. インタラクションと画面遷移

### セキュリティマネージャの有効・無効切り替え
1. ユーザーが設定パネル内の「エージェント制限を有効にする（推奨）」トグルスイッチを **「無効（OFF）」** に変更します。
2. 画面上に **警告確認ダイアログ（Warning Confirmation Alert）** がポップアップ表示されます。
   - **確認メッセージ**: `「セキュリティ制限を無効化すると、AIエージェントによるファイルの破壊、不要なコマンド実行、外部へのデータ送信のリスクが高まります。無効化しますか？」`
3. ユーザーが **「無効化する（続行）」** を選択した場合のみ、セキュリティマネージャが無効（OFF）状態へ移行します。**「キャンセル」** を選択した場合は有効状態（ON）を維持します。
4. 無効状態への移行に伴い、チャットエリアの最上部に **「⚠️ セキュリティ制限が無効化されています」** という赤い警告バナーがスライドイン表示されます。
5. ユーザーがバナー内の **「今すぐ有効に戻す」** ボタン、またはトグルスイッチをONにすることで、いつでも即座にセキュリティ制限を有効化できます。

```
+-------------------------------------------------------------+
| [Warning] セキュリティ制限の無効化                          |
|                                                             |
| セキュリティ制限を無効化すると、AIエージェントによるファイル|
| の破壊、不要なコマンド実行、外部へのデータ送信のリスクが高まります。 |
| 本当に無効化しますか？                                      |
|                                                             |
|               [ キャンセル ]   [ 無効化する (非推奨) ]      |
+-------------------------------------------------------------+
```

### 自動復帰（タイマー）の連動動作
- セキュリティ制限を一時的に無効化した際、ユーザーの消し忘れを防止するために、設定された時間（デフォルト: 10分）を計測するカウントダウンタイマーがバックグラウンドで始動します。
- タイマーが終了すると、システムは自動的にセキュリティマネージャを **「有効（ON）」** に切り替え、赤い警告バナーを非表示にします。
- 自動再有効化が作動した際、チャットの会話ストリーム内またはシステム通知領域に `「安全のため、セキュリティ制限を自動的に再有効化しました。」` というインフォメーションメッセージを追記します。

## 4. 詳細なUI/UX動作（ビジネスルール）

### 1. 異常検知時の警告ポップアップとチャット内表示
エージェントがルールに違反する操作を実行しようとした場合、以下の二段階でユーザーに制限の発生を伝達します。

#### A. 割り込みダイアログ（モーダル警告）
実行スレッドを即時に遮断（ブロック）し、以下の内容を含む警告ダイアログを表示します。
- **ブロック理由**: 例「ファイルアクセスのセキュリティポリシーに違反しました」
- **試行された操作の詳細**:
  - カテゴリ: `ファイルアクセス`
  - 対象パス / コマンド / URL: `/etc/passwd`（または `rm -rf /` 等）
- **検知されたコンテキスト**: どのエージェント/チャットセッションから実行されたか
- **アクションボタン**: `「ルールを編集する」`, `「ブロックを閉じる」`
  - 「ルールを編集する」をクリックした場合、直接ルール編集エディタに遷移し、対象のパス等を許可リストに追加するためのテンプレートが挿入されます。

#### B. チャット内のエラー反映
エージェントとの対話が途切れないよう、チャットの応答部分に赤い枠線付きのエラーメッセージボックスを自動挿入します。
- **表示内容**: `[セキュリティエラー] 許可されていない操作「/etc/passwd」への書き込みを検知したため、実行をブロックしました。`

### 2. 監査ログ（監査履歴）の表示パネル
設定パネルの下部に、過去に発生したセキュリティポリシー違反の履歴を表示する「監査ログ」テーブルを配置します。

| 発生日時 | カテゴリ | 試行された操作内容 | 判定結果 | アクション |
| :--- | :--- | :--- | :--- | :--- |
| 2025-02-18 10:20:15 | 外部プログラム実行 | `rm -rf /workspace` | **ブロック** (Deny) | [ルールを許可に追加] |
| 2025-02-18 10:25:32 | HTTP URL接続 | `https://malicious-site.com/` | **ブロック** (Deny) | [ルールを許可に追加] |
| 2025-02-18 10:30:10 | ファイルアクセス | `/workspace/src/Main.java` | **許可** (Allow) | - |

- **ワンクリック追加機能**: 監査ログの「ルールを許可に追加」ボタンを押すことで、そのブロックされた操作に合致する許可パターンがルール定義テキスト（`.conf`）へ自動生成・挿入される支援機能を提供します。
