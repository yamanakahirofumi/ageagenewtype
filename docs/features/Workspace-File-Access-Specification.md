# ワークスペースファイル読み取り機能仕様書

本ドキュメントでは、AIが必要に応じてワークスペース内のファイル情報を能動的に取得するための「ワークスペースファイル読み取り機能」の仕様を定義します。

---

## 1. 概要

### 背景と目的
従来のAIチャット機能では、現在エディタで開いているファイルや選択範囲のみをチャットのコンテキストとして渡すことができました。しかし、複雑な不具合の修正や複数ファイルにまたがるコード設計を行う際、AI自身が必要なファイルを能動的に探索・読み取れる方が、ユーザーの手動コピペ作業を省き、より正確で迅速な支援を可能にします。
本機能は、LangChain4jのTool（Function Calling）を活用し、AIが必要に応じて自律的にワークスペースのファイルを読み取り、探索できるようにすることを目的とします。

### 基本方針
- **必要に応じた呼び出し（Function Calling）**: プロンプトの内容に応じて、AI自身が「ファイルの中身を読みたい」「フォルダ構成を確認したい」と判断した場合に自動的にツールを実行します。
- **安全性の確保**: [エージェント・セキュリティマネージャ仕様書](Agent-Security-Manager.md)で定義された安全制限ルールを必ず実行前に評価し、許可されたファイルのみアクセス可能にします。
- **簡潔なインタフェース**: ワークスペースのファイルパスは原則として現在のワークスペースディレクトリからの「相対パス」で扱います。

---

## 2. 提供ツールと機能仕様

AIは以下の2つのツールを介してワークスペース内の情報にアクセスします。

### 2.1 readFileContent (ファイル内容の読み取り)
指定された相対パスのファイルからテキストコンテンツを読み込み、AIのコンテキスト（対話履歴）に書き戻します。

- **引数**:
  - `filePath` (String, 必須): ワークスペースルートからの相対パス（例: `src/main/java/net/hero/genai/Main.java`）
- **動作フロー**:
  1. AIが特定ファイルを読み込むツール呼び出しを要求。
  2. システムが、選択中のアクティブワークスペースの絶対パスと結合して絶対ファイルパスを解決。
  3. `SecurityService`を用いて `file-access` カテゴリのアクセス許可判定を実行。
  4. 許可された場合、ファイルをUTF-8として安全に読み取り、結果をAIに返却。
  5. 拒否された場合、エラーメッセージ（アクセス拒否）をAIに返却し、物理的なファイル読み取りは実行しない（監査ログにDENYを記録）。

### 2.2 listWorkspaceFiles (ディレクトリ内容のリスト表示)
指定された相対パス内のファイルおよびサブディレクトリのリストを表示し、AIが必要なファイルを探す手助けをします。

- **引数**:
  - `relativePath` (String, 必須): リスト表示するフォルダの相対パス。ワークスペースルートを表示する場合は空文字 `""` または `.` を指定。
- **動作フロー**:
  1. AIがフォルダのファイル一覧取得を要求。
  2. `SecurityService`を用いて `file-access` のアクセス許可判定を実行。
  3. 許可された場合、該当ディレクトリ配下のファイル・ディレクトリ一覧を `[DIR] name/` または `[FILE] name` の形式でAIに返却。

## 3. セキュリティと権限管理

本機能におけるセキュリティは、すべて [エージェント・セキュリティマネージャ仕様書](Agent-Security-Manager.md) に準拠します。

### 3.1 評価プロセス
1. ツールが実行されると、呼び出し前に `SecurityService.getInstance().checkPermission("file-access", absolutePath, workspacePath)` が呼び出されます。
2. 許可された操作（例: `security_rules.conf` に定義された許可ルール、または安全トグルがOFFの状態）の場合のみ実行。
3. 機密ファイル（例: `security_rules.conf` の `docs/secrets/*` 等の拒否ルールにマッチするファイル）に対しては、物理的な読み込みを遮断し、監査ログにブロック履歴を保存します。

## 4. ユースケース例

### シナリオ1: 特定クラスのバグ調査
- **ユーザー指示**: 「`WorkspaceFileService.java` でIOエラーが発生した時の処理はどうなっている？」
- **AIの挙動**:
  1. 該当クラスのソースコードを読み取る必要があると判断。
  2. `readFileContent("src/main/java/net/hero/genai/workspace/WorkspaceFileService.java")` ツールを呼び出す。
  3. ツールが返したソースコードを解析。
  4. ユーザーに対して、例外のラップ処理やロギングの仕組みを的確に説明。

### シナリオ2: ディレクトリ階層からのファイル特定
- **ユーザー指示**: 「このプロジェクトの設定ファイルはどこにある？」
- **AIの挙動**:
  1. `listWorkspaceFiles(".")` を呼び出してルートフォルダの構成を確認。
  2. `pom.xml` や `security_rules.conf` の存在を確認。
  3. `listWorkspaceFiles("src/main/resources")` などを呼び出してリソースフォルダの中身を確認。
  4. 目的の設定ファイルのパスをユーザーに提示。
