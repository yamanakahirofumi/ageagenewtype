# 利用者・サポートAI・ワークフローAI協調動作仕様書

本仕様書は、本アプリケーションにおける**利用者**、**サポートAI**、および**ワークフローAI**の3者による対話および協調動作プロセスの詳細について定義します。

---

## 1. 概要と基本コンセプト

本システムでは、複雑な開発・執筆作業を安全かつ高品質に進めるため、役割の異なる2つのAIモデル（**サポートAI**および**ワークフローAI**）が協調して動作する構造を採用しています。
利用者は、画面上のインターフェースを通じてワークフローAIと対話しているように見えますが、そのやり取りの前後においてサポートAIが介入・中継し、情報の補完やセキュリティチェック、追加情報の付加などを行います。

---

## 2. 登場人物と役割定義

本システムにおける3つのアクターの役割は、以下の通り定義されます。

| 登場人物 | 役割 | 主な責務 |
| :--- | :--- | :--- |
| **利用者 (User)** | 主体 | システムに対して要望（プロンプト）を送り、成果物の確認や、AIからの質問に対するフィードバックを行います。 |
| **サポートAI (Support AI)** | 中継・補助 | ワークフローAIへのメッセージ送信時における中継（事前判定、追加コンテキストのプリフェッチ等）と、ワークフローAIからの出力結果に対する追加情報の付加を行います。特に、**ワークフローの決定**、**特殊命令の検知**、および**ファイルなどの外部アクセスの有無の把握**に責任を持ちます。 |
| **ワークフローAI (Workflow AI)** | 実行主体 | 選択された、または動的に構築されたワークフローを順次消化し、具体的な成果物の生成、修正、および自己検証を行います。 |

---

## 3. 利用者からワークフローAIへのメッセージ送信（サポートAIによる中継）

利用者がチャット入力欄にメッセージを入力して送信した際、メッセージは直接ワークフローAIに渡されるのではなく、**サポートAIが中継**します。この際、サポートAIは主に以下の**3つの重要な解析と把握**、およびそれに基づく中継処理を行います。

### 3.1. 特殊命令の検知とダイレクト応答
- 入力メッセージに、定義済みワークフロー一覧の照会など特定の**特殊命令（キーワードなど）**が含まれているかを検知します。
- 例えば、「どんなワークフローがあるか」や「list workflows」といった問い合わせを検知した場合、サポートAIは重いAIモデル（Ollama API）を呼び出すことなく、ローカル情報から瞬時にワークフロー一覧を取得してチャットにダイレクト応答を差し込みます。詳細は [ワークフロー機能仕様書](Workflow-Specification.md) を参照してください。

### 3.2. ワークフローの決定 (Workflow Determination)
- 利用者の入力メッセージの意図を分析し、最適なワークフロー（標準チャット、内蔵ワークフロー、あるいは動的生成ワークフロー）を**決定**します。
- このフェーズはワークフローAIセッションが開始される前の重要なマイルストーンです。

### 3.3. 不足情報の収集 (GATHERING) とワークフローAIの不在
- 入力が曖昧な場合、サポートAIはステータスを `GATHERING` と判定し、利用者に追加情報を求める質問を投げます。十分な情報が揃うまでこの対話が繰り返されます。
- **重要なライフサイクルルール**：
  - **ワークフローが決定（DETERMINED）して利用者がそれを承認（Approve）するまでの間、ワークフローAIのインスタンスやセッションは存在しません（有効化されません）。**
  - この決定前フェーズにおけるすべての質問や応答出力は、**純粋にサポートAIの出力として利用者に直接返されます**。
  - ワークフローが確定し、利用者の明示的な合意（Approve）を得て初めて、ワークフローAIのセッションが立ち上がり、タスクの実行フェーズ（ワークフロー消化）が開始されます。

### 3.4. 外部アクセスの有無の把握とファイルのプリフェッチ
- サポートAIは、利用者の指示を遂行するために、ワークスペース内のファイルやリソース、またはネットワーク等の外部へのアクセスが必要であるかを**把握**します。
- 外部ファイルへのアクセスが必要と判定された場合、[セキュリティマネージャ（SecurityService）](Agent-Security-Manager.md)のアクセス制限や規則を事前に評価します。
- 許可されている範囲のファイルであれば、サポートAIがそれを安全に読み込んでコンテキスト情報として収集（プリフェッチ）し、ワークフローAIへの中継メッセージの末尾に**追加情報（コンテキスト）**として統合・添付します。
- この動作により、ツール呼び出し（Tool-calling）機能を持たない軽量なワークフローAIモデルであっても、必要なファイル情報を把握・参照した状態で、安全かつ精度の高いワークフロー処理を開始することが可能になります。詳細は [ワークスペースファイル読み取り機能仕様書](Workspace-File-Access-Specification.md) を参照してください。

## 4. ワークフローAIによるワークフローの消化と対話ループ

サポートAIによって補完・中継された要求メッセージを受け取った後、**ワークフローAI**は指定されたワークフローの消化を開始します。

### 4.1. ワークフローの順次実行
- ワークフローAIは、各ステップ（タスク）を定義に従って順次実行します。
- 出力タスクの後には、必ず検証タスクを実行する「Output-then-Verify」原則に従い、自己修復ループやビルド検証（`mvn clean test` 等）を行います。

### 4.2. 一回のセッションでタスクが完了しない場合の挙動
- ワークフローの性質やタスクの複雑さ、あるいは設計上の不確実性により、ワークフローAIは一回のメッセージングセッションでタスクを完了できない場合があります。
- この場合、ワークフローAIは利用者に質問や確認を投げかけるため、出力に `CLARIFICATION_REQUIRED` というキーワード/マーカーを付与して一時停止します。
- **情報収集ループ（段階的確認）**：
  - システムは進行を一時停止し、ワークフローAIからの質問を利用者に提示します。
  - 利用者が回答を入力して再送信すると、その回答内容が現在のステップの文脈（フィードバック）に追加されます。
  - システムは、ワークフローを次のステップに進めず、**同じステップ**をもう一度ワークフローAIに再実行させます。
  - `CLARIFICATION_REQUIRED` が出力されなくなるまで、同じフェーズに留まったまま情報収集と再実行の対話ループが継続されます。

## 5. ワークフローAIの出力に対するサポートAIの関与（一方向の情報付加）

ワークフローAIの処理が一段落した、あるいは一時停止した際、出力された結果に対して**サポートAIが関与し、追加情報を付加**することがあります。

### 5.1. 付加情報の例
- **セキュリティ警告 / 実行ログ**：[エージェント・セキュリティマネージャ仕様書](Agent-Security-Manager.md) に基づき、ワークフローAIがアクセスを試みたリソースや、自動検証中に検知された疑わしい通信、ファイルアクセスの監査ログ情報など。
- **実行状態 / ステータス可視化**：現在のワークフロー進行度や、検証ステップが自動フォールバック（差し戻しループ）した回数などの統計情報。

### 5.2. 情報伝達に関する重要制限（フィードバック不可ルール）
- サポートAIが関与してワークフローAIの出力に付加したこれら追加情報は、**利用者に対してのみ伝達（表示）**されます。
- **ワークフローAIの文脈（会話履歴や今後のプロンプトコンテキスト）に、これらの付加情報がフィードバックされてはなりません。**
- **理由**：
  - サポートAIによるセキュリティ監査結果や警告、内部ステータス情報などのメタ情報がワークフローAI自身のコンテキストに混入すると、ワークフローAIがそれらのメタ情報を「自分への新たな指示」や「前提条件」と誤解してしまい、対話ループの混乱や無限ループ（AI同士の対話状態）を引き起こすリスクがあるためです。
  - ワークフローAIを本来の「タスク実行/ワークフロー消化」に専念させるため、システムはワークフローAIのコンテキストを純粋なワークフロー状態および利用者の直接的な入力・回答のみに制限します。
