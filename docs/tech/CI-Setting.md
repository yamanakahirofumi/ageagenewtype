# CI/CD 設定

本プロジェクトでは、GitHub Actions を使用して継続的インテグレーション（CI）を行っています。

## 1. GitHub Actions 設定

現在、以下の2つのワークフローが定義されています。

### 1.1 行数カウントとバッジ更新 (`badge-update.yml`)
メインブランチへのプッシュ時に、ソースコードおよびドキュメントの規模を可視化するためのバッジを更新します。

- **トリガー**: `main` ブランチへのプッシュ（`src/**`, `docs/**`, `README.md` の変更時）。
- **主なプロセス**:
    1. **チェックアウト**: リポジトリのソースコードを取得。
    2. **行数カウント**: `src/main` 配下の Java ファイル、および `docs` 配下の Markdown ファイルの行数をカウント。
    3. **バッジ更新**: `README.md` 内の Java および Markdown の行数バッジを `sed` コマンドで置換。
    4. **自動コミット**: 更新された `README.md` をリポジトリにプッシュ（`[skip ci]` タグを使用してループを防止）。

### 1.2 ビルドとテスト (`maven-build.yml`)
コードの変更がビルドやテストに影響を与えていないかを自動的に検証します。

- **トリガー**: `main` ブランチへのプッシュ（`src/**`, `pom.xml` の変更時）、および `main` ブランチへのプルリクエスト。
- **主なプロセス**:
    1. **チェックアウト**: リポジトリのソースコードを取得。
    2. **JDK セットアップ**: JDK 25 (Temurin) をセットアップ。Maven キャッシュを有効化。
    3. **ビルド・検証**: `mvn verify` を実行。コンパイル、JUnit によるテスト実行、および JaCoCo によるカバレッジレポートの生成が行われます。

## 2. CI の目的
- **規模の可視化**：コード（Java）およびドキュメント（Markdown）の行数を計測し、プロジェクトの成長を定量的に把握します。
- **品質の維持**：常にビルドが通る状態を維持し、意図しない破壊的変更を早期に発見します。
- **カバレッジの可視化**：テストの網羅率を測定し、テスト不足の箇所を特定します。
- **継続的な配布準備（将来計画）**：カスタム JRE を含む配布用パッケージの自動生成を検討しています。
